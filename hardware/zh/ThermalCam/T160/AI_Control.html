MS-T160 AI 接入

2026-11-18
编辑本页
更新历史
日期 版本 作者 更新内容
2026-11-18 v0.1 Sipeed
  • 初始化文档：直接调用 HTTP、MCP server 接入与常见问题
  • 新增让 AI 修改网页

AI 接入

T160 机身里没有大模型。它通过 USB 网卡提供 HTTP 接口，把温度和画面开放出来，AI 工具只要能发 HTTP 请求，就能读取这些数据并给出结论，例如"板子上哪个元件最热""这一分钟温度有没有上升"。

不需要额外的服务器，也不需要安装 SDK。有两种接法：

  • 直接调用 HTTP（推荐）：AI 工具能执行命令（curl、Python 等）时，直接让它访问接口，最简单。
  • 通过 MCP：AI 工具支持 MCP 时，在电脑上运行随附的 MCP server，把接口变成固定的工具，模型不用每次自己拼命令。本文以 OpenCode 为例。

两种方式读到的数据完全一样，MCP server 只是一个转接层，不是必须的。

除了读取数据，还可以让 AI 帮你修改 T160 的网页，见让 AI 修改网页。

工作原理

方式一：AI 工具 --HTTP--> T160  http://192.168.17.1

方式二：AI 工具 --MCP--> t160_mcp_server.py
                --HTTP--> T160  http://192.168.17.1
  • 两种方式读的都是 /api/v1/thermal、/frame.temp8 这些接口，详见进阶使用与开发。
  • MCP server 运行在电脑上，只提供读取类工具，不会修改设备设置。

使用前准备

开始前，请先确认：

  • T160 已插在电脑上，浏览器可以打开 http://192.168.17.1 并看到画面。
  • 方式一：AI 工具能够执行本地命令，例如 Claude Code、OpenCode、Cursor 等。
  • 方式二：电脑已安装 Python 3.8 或更高版本，AI 工具支持 MCP（例如 OpenCode）。

方式一：直接调用 HTTP（推荐）

先确认接口

curl http://192.168.17.1/api/v1/thermal

能返回带 "valid":true 的温度 JSON 就可以用了。

在对话里说明取数规则

在对话开头把规则讲清楚，比每次口头叮嘱可靠：

你现在接了一台 Sipeed MS-T160 热成像仪，接口在 http://192.168.17.1。
读数规则：
1. 温度只从 /api/v1/thermal 读取，逐像素数据用 /frame.temp8（格式见 T160 文档）；
2. 回答时带上帧号和坐标，坐标基于 160×120 的原始横向画面；
3. 判断温度趋势前至少采样 5 次；
4. 不要读 /stream.temp8，以免和网页抢画面；
5. 只读接口可以直接用，修改网段、更新固件等写操作必须先问我；
6. 读不到数据就如实说明，不要编造。

之后正常提问即可，AI 会自己执行 curl 或 Python 取数。

使用示例

使用 T160，读取当前最高温度，并告诉我它在画面里的位置。

使用 T160，观察 10 秒，告诉我温度是在上升还是已经稳定。

使用 T160，每隔 5 秒读一次温度，连续读 1 分钟，超过 60 ℃ 时提醒我。

建议从简单、可确认的操作开始，例如先读一次温度，再看一次趋势。

温度以接口返回的数值为准。照片里的颜色只表示相对冷热，AI 如果从画面颜色估算温度，得到的数字不要采信。

方式二：通过 MCP（可选）

如果希望把读取接口固定成工具，或者 AI 工具只能通过 MCP 接入工具，就运行随附的 MCP server。

准备脚本

把 t160_mcp_server.py 保存到电脑上，例如用户目录下的 t160 文件夹。

脚本用环境变量 T160_BASE 指定设备地址，默认是 http://192.168.17.1。设备改过网段时，在配置里修改这个变量即可，脚本不用改。

脚本只使用 Python 标准库，不需要安装其他依赖。Windows 上一般使用 python 命令，Linux 和 macOS 上一般使用 python3。

在 OpenCode 中添加 MCP

可以直接用命令行添加，OpenCode 会按当前版本写入正确的配置结构：

opencode mcp add t160 --env T160_BASE=http://192.168.17.1 -- python3 /path/to/t160_mcp_server.py

也可以手动编辑配置文件。全局配置放在 ~/.config/opencode/opencode.json，也可以放在项目目录下的 opencode.json。如果文件里已经有其他 MCP server，在 mcp 下再加一个 t160 项即可：

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "t160": {
      "type": "local",
      "command": ["python3", "/path/to/t160_mcp_server.py"],
      "environment": { "T160_BASE": "http://192.168.17.1" }
    }
  }
}

新版 OpenCode 把 server 放在 mcp.servers 下。如果你的配置已经是 "mcp": { "servers": { ... } } 的结构，把 t160 放进 servers 里，字段不变。

其中：

  • type 固定为 local，表示由 OpenCode 在本机启动这个进程。
  • command 是启动命令，第一个元素是 Python 命令，第二个是脚本路径。
  • environment 里的 T160_BASE 是设备地址。

保存后重新打开 OpenCode，server 会自动连接。在 OpenCode 里执行 /mcps，能看到 t160 处于 connected 状态即可。

确认连接

工具列表中应该能看到 t160 提供的四个工具：

工具 用途
t160_device_info 型号、固件、分辨率、支持的格式
t160_thermal 当前帧的中心、最高、最低温度和坐标
t160_capture 抓一帧画面，生成和网页方向一致的铁红配色 PNG，并返回同一帧的温度
t160_watch 在一段时间内采样温度，返回变化趋势

先发一句简单的话测试：

使用 T160 读取当前温度，告诉我最高温是多少、在画面哪个位置。

AI 应该调用 t160_thermal 并给出具体数值。

让 AI 修改网页

T160 的网页就是一个单独的 HTML 文件，没有构建步骤，很适合交给 AI 修改。例如换一套配色和布局、把常用按钮放大、加上自己的说明文字，或者做一个专门用于某种检测场景的界面。改好的网页上传到 T160 后会替换内置网页，重启和固件更新后都会保留。

修改流程

先下载内置网页的源码：

curl http://192.168.17.1/builtin -o t160.html

也可以在浏览器打开 http://192.168.17.1/builtin，查看网页源代码，全选复制后保存为 t160.html。不要用浏览器的"另存为"，存下来的可能是运行后改动过的页面，也可能被拆成多个文件。

然后：

  1. 把 t160.html 交给 AI，先发下面的修改规则，再说清楚你想要的效果。
  2. 上传改好的文件：在网页的"设备设置与固件更新"面板中找到"自定义网页外观"，选择文件后点上传并应用。也可以用命令上传。
  3. 刷新页面查看效果。不满意就把问题告诉 AI，改好后再上传。

建议一次只改一处，确认没问题再改下一处，出错时容易找到原因。把每次的修改要求保存下来，以后更新固件时还用得上。

修改规则

把下面这段发给 AI，作为修改时必须遵守的规则：

附件 t160.html 是 Sipeed MS-T160 热成像仪的内置网页。设备通过 USB 网卡提供 HTTP 服务，地址是 http://192.168.17.1，网页上传后由设备直接提供。
请在这个文件的基础上修改，并遵守以下规则：
1. 结果仍然是一个完整的 HTML 文件，UTF-8 编码，总大小不超过 126976 字节（124 KiB）。原文件约 98 KB，只剩约 28 KB 余量，新增内容尽量精简。
2. 不要引用任何外网资源，包括 CDN 脚本、在线字体和外链图片，使用时手机或电脑可能没有网络。图标用内联 SVG，图片用 data URI。
3. 接口一律用相对路径（例如 /frame.temp8），不要写死 192.168.17.1，这样设备改过网段后也能用。
4. 除非我明确要求，不要改动这些部分：读取 /frame.temp8 和 /stream.temp8 的代码、120 字节元数据的解析和温度换算、超分（createGpuSr 函数里的 WebGL 代码，以及 /assets/sr-fast.wasm、/assets/sr-fast-simd.wasm、/assets/sr-fast.bin）、画面旋转，以及 <canvas id="view"> 和 #overlay。
5. 保留"设备设置与固件更新"面板，尤其是"恢复内置网页"和固件更新功能。
6. 写操作（上传网页、更新固件、修改网段）必须带请求头 X-Sipeed-Request: 1。
7. 改完后列出改动点和文件大小。上传到设备之前先问我。

用命令上传和恢复

能执行命令的 AI 工具也可以直接上传。上传会写入设备的 Flash，请先确认改动，再让 AI 执行；写入时不要拔出设备。

# 查看当前状态：是否在用自定义网页、已用大小和上限
curl http://192.168.17.1/api/v1/web

# 上传自定义网页
curl -X POST http://192.168.17.1/api/v1/web \
  -H 'Content-Type: text/html' \
  -H 'X-Sipeed-Request: 1' \
  --data-binary @t160.html

# 删除自定义网页，恢复内置网页
curl -X DELETE http://192.168.17.1/api/v1/web \
  -H 'X-Sipeed-Request: 1'

上传成功会返回 {"ok":true,"custom":true,"bytes":...}。返回 400 通常是缺少请求头，或者文件超过 124 KiB；返回 409 表示上一次上传还没结束，稍后再试。

改坏了怎么办

用浏览器打开 http://192.168.17.1/builtin，内置网页始终可以访问。在它的"设备设置与固件更新"面板里点恢复内置网页，或者执行上面的删除命令，就能删掉自定义网页。

常见问题

AI 一定要通过 MCP 吗

不需要。能执行命令的 AI 工具直接调用 HTTP 就行；MCP 只是把接口固定成工具，减少模型自由拼命令。

AI 读不到数据

请检查：

  • T160 是否已插好，浏览器能否打开 http://192.168.17.1。
  • curl http://192.168.17.1/api/v1/thermal 是否正常返回。
  • AI 工具是否有权限执行命令、访问本机网络。

AI 工具里看不到 t160 工具

请检查：

  • 保存配置后，是否完全退出了 AI 工具再重新打开。
  • mcp 下的层级和字段名是否正确，type 是否为 local。
  • command 里的 Python 命令能否在终端中直接运行，例如执行 python3 --version。
  • 脚本路径是否正确。也可以先在终端里运行一次 python3 t160_mcp_server.py，确认没有报错（运行后会等待输入，按 Ctrl+C 退出即可）。

AI 读到的温度无效

设备刚插上时可能还没有可用的画面，接口会返回 "valid": false。等 1 ~ 2 秒再读；如果一直如此，先在浏览器中打开 /api/v1/thermal 确认接口本身是否正常。

AI 一读数据，网页画面就卡住

AI 很可能读了 /stream.temp8。T160 同一时间只服务一个连续流，会和网页互相抢。让 AI 改用 /api/v1/thermal 或 /frame.temp8。

Windows 上提示找不到 python3

Windows 的 Python 命令通常是 python，把配置中 command 的第一个元素改成 python 即可。

设备换了网段后 AI 读不到数据

直接调用 HTTP 时，把对话里的地址改成新的 192.168.<网段>.1；通过 MCP 时，修改配置里的 T160_BASE，保存后重启 AI 工具。

AI 给出的温度和网页显示不一致

常见原因：

  • 两边读的不是同一帧，温度本身在变化。
  • 被测表面发射率低，例如光亮的金属，见常见问题。
  • AI 用画面颜色估算了温度，而不是接口数据。

更新固件后，自定义网页不正常

自定义网页在固件更新后会保留，但新固件的内置网页可能改了接口或功能。重新下载新的 /builtin，把之前的修改要求再发给 AI，让它在新文件上重新修改。

上传时提示文件太大

自定义网页最大 124 KiB。让 AI 精简：删掉用不到的功能，把图片换成 SVG 或压缩后再内嵌。

安全注意事项

  • 只连接可信的 AI 工具。
  • T160 的接口没有登录验证，只应通过 USB 直连使用，不要转发到局域网或公网。
  • 在对话规则里禁止写操作；修改网段、更新固件由人手动执行。
  • 让 AI 修改网页时，先看过它列出的改动，确认后再上传。
  • 不要让 AI 在无人值守的情况下长时间连续采集。
